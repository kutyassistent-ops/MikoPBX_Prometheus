# Обзор модуля

## Назначение

ModulePrometheus даёт возможность мониторить MikoPBX в Prometheus + Grafana.
Модуль запускает на АТС лёгкий HTTP-экспортер, который на каждый запрос
собирает метрики и отдаёт их в стандартном формате Prometheus
(`text/plain; version=0.0.4`).

Модель работы — **pull**: сервер Prometheus сам периодически опрашивает
АТС. В отличие от Zabbix-модуля здесь не нужен ни демон-агент,
отправляющий данные, ни шаблоны: конфигурация — это фрагмент
`prometheus.yml`, правила алертинга живут на стороне Prometheus.

## Что мониторится

- **Система АТС** — uptime, load average, память и swap, CPU по ядрам,
  дисковые разделы **с инодами**, сетевые счётчики с ошибками и потерями,
  процессы, потоки, файловые дескрипторы.
- **Asterisk** — доступность, версия, uptime, время последнего reload,
  активные каналы, разбивка каналов по технологии, очереди, конференции,
  качество RTP по каналам.
- **Телефония MikoPBX** — активные вызовы с разбивкой по направлению,
  SIP-пиры (всего, онлайн, доля, разбивка по состояниям).
- **Транки** — состояние каждого SIP/IAX-транка, агрегированные счётчики,
  загрузка каналов, смены состояния регистрации.
- **Статистика звонков** — скользящее окно час/сутки: всего, отвечено,
  длительность, billsec, ASR, ACD, среднее время звонка, разбивка по
  причине завершения, короткие и длинные звонки, пропущенные по внутренним.
- **Платформа** — размеры баз данных, `mysqladmin status`, локальный
  nginx_status, синхронизация времени, OOM-киллы и паники ядра, состояние
  модулей расширений, рантайм PHP (память, OPcache, GC, дескрипторы).
- **Сам экспортёр** — аптайм, память, число запросов и скрейпов, ошибки
  и таймауты сборки, отказы по авторизации, ответы по HTTP-кодам, время
  каждого сборщика, конфигурация, состояние необязательных блоков.

Полный каталог — в [[Справочник метрик|справочнике метрик]].

## Отличия от модуля Zabbix

| Аспект | ModuleZabbixAgent5 | ModulePrometheus |
|---|---|---|
| Транспорт | push-агент `zabbix_agentd` + протокол Zabbix | pull: HTTP `GET /metrics` |
| Настройка сервера | импорт шаблонов YAML | фрагмент `prometheus.yml` |
| Готовые проверки | items/triggers в шаблоне | alert rules на стороне Prometheus |
| Discovery транков | LLD-правило | labels появляются на каждом скрейпе |
| Системные метрики | парсинг `/proc` в shell | `/proc` в коллекторе экспортера |
| Внешние зависимости | бинарник агента (собирается в CI) | нет — чистый PHP |

## Ограничения текущей версии

> [!warning] Что нужно знать до включения
> - **Авторизация выключена, экспортёр слушает `0.0.0.0`.** Метрики читает
>   любой из сегмента, включая имена всех внешних номеров и состояние
>   транков. Включите токен или закройте порт firewall-правилом.
> - **Метрики очередей, конференций и качества RTP зависят от версии
>   Asterisk.** Формат вывода команд менялся между выпусками; при
>   несовпадении парсер молча отдаёт пустоту. См. [[Траблшутинг]].
> - `collector_success = 1` означает «исключения не было», а не «метрики
>   есть». Сборщик над пустым каталогом кэша тоже равен 1. Что именно
>   не отдало данные, показывают `mikopbx_exporter_block_present` и
>   `mikopbx_exporter_block_absent_reason`.
> - Grafana-дашборд в поставку не входит; готовые правила алертинга — да,
>   в `examples/alerts.yml`.
