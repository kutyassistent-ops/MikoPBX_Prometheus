# Траблшутинг

## Быстрая диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Модуль не устанавливается из zip | Лишний уровень вложенности в архиве | В корне zip должен лежать `module.json` **без папки**. Правильно собирает `build-module.ps1` |
| Статус «Остановлен», PID пустой | Порт занят / ошибка bind / PHP не стартовал | Посмотрите syslog с тегом `ModulePrometheus*`; проверьте порт `netstat -tulpn \| grep 9713` |
| `curl` не отвечает | Firewall или адрес прослушивания | Разрешите подсеть Prometheus в firewall; проверьте, что адрес bind не `127.0.0.1`, если скрейпит внешний сервер |
| `401 unauthorized` | Включён Bearer-токен | Передайте `Authorization: Bearer …` или отключите требование токена в настройках |
| `403 forbidden` | Адрес скрейпера не в списке разрешённых | Добавьте адрес сервера Prometheus в «Разрешённые адреса» на странице модуля |
| `503 service unavailable` | Параллельных сборов больше, чем разрешено | Поднимите «Параллельных сборов» или уменьшите частоту скрейпов |
| `404 not found` на `/metrics` | Нет слеша или другой путь | Путь строго `/metrics`; любой другой путь теперь честно отвечает 404 |
| Таргет в Prometheus DOWN | Сеть/firewall/порт | Сначала `curl` с сервера Prometheus, затем [[Траблшутинг|см. ниже]] |
| Пустые метрики `mikopbx_trunk_calls*` | Кэш ещё не собран | Подождите 5 минут или прогоните `php -f Lib/StatsCache.php` вручную |
| `collector_success{collector="telemetry"} 0` | REST API PBX недоступен | Проверьте, что PBX здоров; смотрите syslog |
| `collector_success{collector="call_stats"} 0` | Ошибка чтения кэша | См. секцию «Кэш статистики» ниже |
| Страница настроек показывает пустые поля | Значения не попали в шаблон | Обновитесь до 1.4.0 — в 1.3.x шаблон не доставал значения массива |

## Страница настроек пустая, а экспортёр работает

Так выглядел модуль 1.3.x: поля были пустыми, хотя воркер отвечал на
своём порту. Причина — Volt не достаёт элемент массива через точечную
запись, значения в шаблон не попадали. В 1.4.0 контроллер отдаёт в шаблон
отдельные переменные. Если после обновления поля всё ещё пустые —
проверьте, что загружена именно 1.4.0 (версия видна в панели статуса
и в `module.json` архива).

> [!warning] Не нажимайте «Сохранить» на сломанной странице
> В 1.3.x сохранение с пустыми полями затирало адрес, порт и пути к
> сертификату. В 1.4.0 пустое поле токена сохраняет старый токен, а
> остальные значения приходят в форму уже заполненными.

## Скрейп не укладывается в таймаут

```promql
increase(mikopbx_exporter_scrape_timeouts_total[1h])
```

Сбор прерывается по истечении `scrape_timeout` — в этом и смысл: лучше
ошибка, чем «половина метрик, которая выглядит как полная». Чаще всего
мешает сборщик `asterisk` (каждая команда форкает процесс и открывает
AMI) — поднимите бюджет в настройках модуля; `scrape_timeout` на стороне
Prometheus должен быть ещё больше.

## Модуль установился, но воркер не стартует

1. Проверьте syslog:

```sh
grep ModulePrometheus /var/log/messages | tail -20
```

2. Запустите воркер в foreground — ошибка будет видна сразу:

```sh
php -f /storage/usbdisk1/mikopbx/custom_modules/ModulePrometheus/Lib/WorkerPrometheusExporter.php start
```

Типичные причины:

- **«Cannot bind tcp://…»** — порт занят другим процессом или нет прав.
  Смените порт в настройках модуля.
- **PHP-ошибка** — смотрите текст исключения; проверьте, что версия
  MikoPBX соответствует требованиям (2025.1.1+).
- **Файл не исполняемый** — модуль обычно чинит права сам, но можно
  вручную: `chmod 755 bin/prometheus-exporter bin/*.sh`.

> [!tip] Воркер должен завершаться не сразу
> При успешном старте процесс висит в foreground и ждёт соединений —
> это нормально, `Ctrl+C` для выхода.

## Таргет DOWN в Prometheus

Выполните на сервере Prometheus:

```sh
curl -v http://<АТС>:9713/-/healthy
```

- **Connection refused** — воркер не слушает (см. предыдущую секцию)
  или адрес прослушивания ограничен localhost.
- **Timeout** — firewall на АТС блокирует порт; проверьте правило
  модуля **Prometheus** и подсеть.
- **401** — нужен токен в конфиге scrape (`authorization.credentials`).

Если `curl` работает, а Prometheus — нет, проверьте
`Status → Targets` и сообщение об ошибке таргета в интерфейсе Prometheus.

## Авторизация

```yaml
# prometheus.yml
    authorization:
      credentials: 'токен-из-настроек-модуля'
```

> [!warning] Токен в открытом виде
> Файл `prometheus.yml` содержит токен в plaintext. Ограничьте права
> на файл на сервере Prometheus. Если доверенной сети нет — включите
> HTTPS в настройках модуля и добавьте `scheme: https` в `scrape_configs`.

## Кэш статистики

Проверьте каталог:

```sh
ls -la /storage/usbdisk1/mikopbx/tmp/ModulePrometheus/
```

Ожидаемые файлы: `trunkCalls_*` (по 12 файлов на транк), `last_update`,
`collector.lock`.

- **Каталог пуст** — cron-задача не выполняется. Проверьте задачу
  `prometheus-stats-cache.sh` в cron MikoPBX; прогоните скрипт вручную.
- **Файлы есть, но старые** — посмотрите `last_update`; записи CDR за
  период могут отсутствовать (нет звонков — значения нулевые, это норма).
- **Файлы исчезают** — коллектор чистит кэш для транков, которых больше
  нет; если транк существует, проверьте его ID в интерфейсе.

> [!note] Это не ошибка
> Метрика `mikopbx_trunk_calls` может быть равна 0 — если за последний
> час через транк не было звонков. Отличайте от «кэш не работает» по
> `mikopbx_stats_cache_age_seconds` (должен быть меньше ~600).

## Диск «полон», а `df` показывает место

```promql
mikopbx_system_filesystem_inodes_used_ratio
```

Значение 1.0 при сотнях гигабайт свободных байтов — это забитые иноды,
а не байты. `df -h` про это не скажет. Наблюдалось на `/cf` и
`/storage/usbdisk1`.

## Свободных дескрипторов 0

```promql
mikopbx_system_file_descriptors_free
```

Ноль означает, что новая сессия не откроется: SSH, HTTP и сам экспортёр
перестанут принимать соединения. Сверьте с
`/proc/sys/fs/file-max` и `cat /proc/sys/fs/nr_open`.

## Метрики системы странные

- **CPU отдаётся counter'ом, а не процентом** — с версии 1.1.0 это
  `mikopbx_system_cpu_seconds_total`. С 1.4.0 значения идут в **секундах**,
  поэтому `/ 100` в формуле больше не нужен:
  `sum(rate(mikopbx_system_cpu_seconds_total{mode!="idle", cpu!="all"}[5m])) / count(count by (cpu) (mikopbx_system_cpu_seconds_total{cpu!="all"}))`
  Метрики `mikopbx_system_cpu_busy_ratio` больше нет.
- **`free_bytes` больше, чем раньше** — теперь это «свободно всем»,
  включая резерв ФС (обычно 5%). Если нужен объём, который реально можно
  записать, берите `mikopbx_system_filesystem_available_bytes`.
- **Диск показывает не тот раздел** — фильтруйте по
  `mountpoint`/`fstype`; в метрики попадают только реальные ФС
  (ext/xfs/btrfs/f2fs/vfat/overlay/squashfs).
- **Сеть без `eth0`** — имя интерфейса на этой АТС может отличаться;
  посмотрите фактические значения label `device`.

## Метрика пропала, а сборщик зелёный

> [!warning] `collector_success = 1` не значит «метрики есть»
> Значение 1 означает «исключения не было». Сборщик `call_stats` полдня
> отдавал `success = 1` при **нуле** метрик, потому что каталог кэша был
> пуст, а пустой каталог — это «нечего читать», а не ошибка.

Проверять надо наличие метрик, а не флаги:

```bash
curl -s http://127.0.0.1:9713/metrics | grep -c '^# HELP mikopbx_'
```

Если семейство пропало у одного сборщика, смотрите его `duration_seconds`:
округлённые до нуля секунды означают, что он упал на первой же строке.

```promql
mikopbx_exporter_block_error_info
```

покажет, какой необязательный блок упал и с каким текстом ошибки.

С 1.4.0 есть и более общий ответ на вопрос «а что именно не работает»:

```promql
mikopbx_exporter_block_present == 0
```

а `mikopbx_exporter_block_absent_reason` объяснит причину — например
«mysqladmin is not installed». Раньше такой блок просто молча исчезал из
ответа, и отличить «утилиты нет» от «нулевого значения» было нельзя.

## Очереди, конференции и качество RTP не появляются

Сборщик `asterisk` держит `success = 1`, но эти семейства не выдаются.
Парсеры **молча возвращают пустоту**, если вывод команды не совпал с
ожидаемым: формат `queue show`, `conference show` и
`pjsip show channelstats` различается между выпусками Asterisk.

Проверьте на АТС, что команды вообще есть и что они выводят:

```bash
asterisk -rx 'queue show'
asterisk -rx 'conference show'
asterisk -rx 'pjsip show channelstats'
```

Если команда не существует, экспортёр получает `No such command` и
пропускает блок — метрик не будет, а ошибки в логах тоже не будет.

## Сброс и переустановка

```sh
# Остановить воркер
kill $(busybox ps | grep '[M]odulePrometheusExporter' | busybox awk '{print $1}')
# Удалить кэш
rm -rf /storage/usbdisk1/mikopbx/tmp/ModulePrometheus
```

Затем отключите/включите модуль — воркер и cron поднимутся заново.
