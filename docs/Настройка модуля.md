# Настройка модуля

Все параметры задаются на странице модуля (**Модули → Установленные →
Экспортер Prometheus**) и хранятся в БД MikoPBX.

Форма разбита на четыре секции: **Сеть**, **Доступ**, **HTTPS** и **Сбор**.

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| Адрес прослушивания | `0.0.0.0` | Интерфейс, на котором слушает экспортёр. Принимается и с префиксом (`http://0.0.0.0`), и с портом, и IPv6 в скобках |
| Порт | `9713` | TCP-порт; после смены обновится и firewall-правило |
| Разрешённые адреса | пусто | Список IP или CIDR через запятую. Пусто — доступ с любого адреса. Проверяется экспортёром на каждом подключении, отклонённые получают `403` |
| Требовать bearer-токен | **выключено** | Авторизация включается только явным чекбоксом |
| Bearer-токен | пусто | Используется, только если включён чекбокс выше |
| Отдавать по HTTPS | выключено | Пути к сертификату и ключу; файлы проверяются на читаемость при сохранении |
| Кэш ответа, сек | `0` | Сколько секунд переиспользуется готовый ответ. `0` — сбор на каждый запрос |
| Таймаут сбора, сек | `10` | Публикуется как `mikopbx_exporter_scrape_timeout_seconds`, чтобы Grafana предупреждал до обрыва. Сбор, не уложившийся в бюджет, прерывается, а скрейп считается неуспешным |
| Параллельных сборов | `8` | Сколько скрейпов может собираться одновременно. Сверх лимита — `503` |
| Публиковать RTP по каналам | выключено | Per-channel семейство метрик; по умолчанию только агрегаты |
| Textfile-коллектор | — | Каталог, куда кладутся `.prom`-файлы |

> [!danger] Авторизация по умолчанию выключена
> Свежая установка отдаёт `/metrics` **без** заголовка `Authorization`.
> Это сделано осознанно: пустой токен больше не включает авторизацию
> сам по себе. Если токен нужен — включите чекбокс, иначе сохранённая
> строка останется лежать в базе без эффекта.

> [!warning] Как работает токен
> - Токен **никогда не отправляется в браузер**: поле всегда пустое, а
>   плейсхолдер сообщает, что токен сохранён.
> - Пустое поле при сохранении **не затирает** сохранённый токен.
> - Если чекбокс включён, а токена нет вообще — сохранение отклоняется
>   с ошибкой: иначе экспортёр остался бы открытым всем, кто дотянется
>   до порта, а в интерфейсе было бы написано, что токен требуется.
> - Кнопка «Сгенерировать» создаёт 48 hex-символов через
>   `crypto.getRandomValues`.

> [!info] Перезапуск
> При сохранении настроек воркер перезапускается автоматически
> (хук `modelsEventChangeData`). Кнопка «Перезапустить экспортёр» на
> странице нужна, чтобы сбросить закешированный ответ вручную, не
> меняя настройки.

> [!warning] Плашка о риске
> Если токен не задан, а адрес прослушивания — `0.0.0.0`, страница
> показывает предупреждение: в таком режиме метрики читает любой, кто
> дотягивается до порта.

## Кэш ответа

По умолчанию `0` — каждый запрос собирает метрики заново. Если сбор
занимает больше секунды, а интервал скрейпа 15 секунд, можно поставить
`30`: это снимает половину нагрузки с REST API АТС и почти не влияет на
свежесть данных. Значение видно в `mikopbx_exporter_config_info`.

## Textfile-коллектор

Каталог `.../tmp/ModulePrometheus/textfile`. Любой `.prom`-файл, положенный
туда, добавляется к ответу как есть. Это даёт возможность дописывать
метрики из cron-скриптов, не трогая код модуля:

```bash
cat > /storage/usbdisk1/mikopbx/tmp/ModulePrometheus/textfile/backup.prom <<'EOF'
# HELP backup_age_seconds How long since the last successful backup run
# TYPE backup_age_seconds gauge
backup_age_seconds 7200
EOF
```

Файл больше 1 МБ или файл, который не похож на exposition-документ,
пропускается — сломанный сниппет иначе испортил бы весь ответ.

## Кнопка «Проверить доступность»

Открывает сокет к самому экспортеру с АТС и дёргает `/-/healthy`.
Позволяет отличить «экспортёр упал» от «порт закрыт firewall'ом» —
статус в панели этого различить не может.

## Безопасность

> [!danger] Обязательно ограничьте доступ
> По умолчанию авторизация выключена, а экспортёр слушает `0.0.0.0`.
> Значит метрики читает любой, кто дотягивается до порта — включая имена
> всех внешних номеров и состояние транков. Базовая защита:
> 1. **Список разрешённых адресов** — впишите IP или CIDR сервера
>    Prometheus; остальным экспортёр отвечает `403`.
> 2. **Bearer-токен** — включается чекбоксом на странице модуля.
> 3. **HTTPS** — включается чекбоксом, если доверенной сети нет.
> 4. **Firewall MikoPBX** — модуль добавляет правило на порт; при
>    заполненном списке разрешённых адресов правило создаётся сразу
>    только для них.

Как задать firewall-правило вручную:

1. **Система → Firewall** (или раздел безопасности в вашей сборке).
2. Найдите правило модуля **Prometheus** (порт — выбранный в модуле).
3. Разрешите доступ только подсети, где стоит Prometheus-сервер
   (например `/32` с его адресом).

## Смена порта

1. Задайте новый порт на странице модуля, сохраните.
2. Модуль перезапустит воркер и обновит своё firewall-правило.
3. Не забудьте поправить target в `prometheus.yml`.

> [!tip] Выбор порта
> Если рядом планируется `node_exporter`/`process-exporter`, оставьте им
> стандартные `9100`/`9256`, а этот порт меняйте при конфликте. Порт можно
> проверить на занятость: `netstat -tulpn | grep 9713`.

## Обновление с 1.3.x

Новые колонки (`allowed_source_ip`, `publish_channel_quality`,
`max_concurrent_scrapes`) добавляются установщиком автоматически по
аннотациям модели — ручных действий не требуется. Настройки сохраняются.
