# Справочник метрик

> [!info] Соглашения
> Все метрики имеют префикс `mikopbx_`. Типы: `gauge` — значение на момент
> замера, `counter` — монотонно растущий счётчик (для скорости используйте
> `rate()`). Скользящие окна статистики транков — `gauge` (не `counter!`).

## Экспортер

| Метрика | Тип | Labels | Описание |
|---|---|---|---|
| `mikopbx_exporter_build_info` | gauge | `module`, `version` | Информация о сборке (значение всегда 1) |
| `mikopbx_exporter_up` | gauge | — | 1 — процесс экспортёра отвечает |
| `mikopbx_exporter_start_time_seconds` | gauge | — | Unix-время старта процесса экспортёра |
| `mikopbx_exporter_scrapes_total` | counter | — | Обслужено скрейпов с момента старта |
| `mikopbx_exporter_scrape_failures_total` | counter | — | Скрейпов, завершившихся ошибкой сбора |
| `mikopbx_exporter_scrape_timeouts_total` | counter | — | Скрейпов, прерванных по таймауту сбора |
| `mikopbx_exporter_requests_total` | counter | — | Всего HTTP-запросов с момента старта |
| `mikopbx_exporter_auth_failures_total` | counter | — | Запросов, отклонённых из-за токена |
| `mikopbx_exporter_active_children` | gauge | — | Скрейпов, собираемых прямо сейчас |
| `mikopbx_exporter_http_responses_total` | counter | `code` | Ответов по HTTP-коду |
| `mikopbx_exporter_request_duration_seconds_sum` | counter | — | Суммарное время обслуживания запросов |
| `mikopbx_exporter_request_duration_seconds_average` | gauge | — | Среднее время обслуживания запроса |
| `mikopbx_exporter_config_info` | gauge | `listen_port`, `listen_address`, `auth_enabled`, `tls_enabled`, `scrape_cache_ttl` | Текущие настройки (значение всегда 1) |
| `mikopbx_exporter_scrape_timeout_seconds` | gauge | — | Заявленный бюджет одного скрейпа |
| `mikopbx_exporter_scrape_duration_seconds` | gauge | — | Длительность текущего сбора |
| `mikopbx_exporter_scrape_families` | gauge | — | Сколько семейств отдаёт последний скрейп |
| `mikopbx_exporter_memory_bytes` | gauge | `type` (`current`/`peak`) | Память процесса экспортёра по данным PHP |
| `mikopbx_exporter_gc_runs_total` | counter | — | Сборок мусора в процессе экспортёра |
| `mikopbx_exporter_opcache_enabled` | gauge | — | 1 — OPcache активен |
| `mikopbx_exporter_opcache_memory_bytes` | gauge | `type` (`used`/`free`/`wasted`) | Учёт памяти OPcache |
| `mikopbx_exporter_opcache_hit_ratio` | gauge | — | Доля попаданий OPcache (0..1) |
| `mikopbx_exporter_open_fds` | gauge | — | Открытых дескрипторов в процессе экспортёра |
| `mikopbx_exporter_collector_success` | gauge | `collector` (`system`, `asterisk`, `telemetry`, `call_stats`, `infrastructure`) | 1 — исключений не было, 0 — исключение |
| `mikopbx_exporter_collector_duration_seconds` | gauge | `collector` | Время каждого сборщика в последнем скрейпе |
| `mikopbx_exporter_block_present` | gauge | `block` | 1 — необязательный блок отдал данные, 0 — не отдал |
| `mikopbx_exporter_block_absent_reason` | gauge | `block`, `reason` | Почему блок не отдал данные |
| `mikopbx_exporter_block_error_info` | gauge | `block`, `reason` | Какой блок упал с исключением |

> [!tip] Первый алерт, который стоит завести
> `mikopbx_exporter_collector_success == 0` — мгновенно показывает,
> что какой-то источник метрик отвалился (например, REST API PBX).
> Группы разнесены по источникам, поэтому сразу видно, что именно сломалось,
> а не «телефония целиком».

> [!info] Блоки, которые ничего не отдали
> `mikopbx_exporter_block_present == 0` — блок не применим (нет утилиты,
> нет каталога). `mikopbx_exporter_block_absent_reason` объясняет почему.
> Раньше такие семейства просто исчезали, и отличить «источник недоступен»
> от «нулевого значения» было невозможно.

> [!note] Счётчики живут в родительском процессе
> Каждое соединение обрабатывается форкнутым ребёнком, а счётчики
> агрегируются в родителе: ребёнок отправляет отчёт через socketpair.
> Поэтому в теле метрик значения на одно обновление отстают — это нормально.

| Метрика | Тип | Labels | Описание |
|---|---|---|---|
| `mikopbx_database_size_bytes` | gauge | `database` (`main`/`cdr`) | Размер файлов SQLite |
| `mikopbx_mysql_status` | gauge | `metric` | Значения из `mysqladmin status` |
| `mikopbx_webserver_status` | gauge | `metric` | Счётчики локального nginx_status |
| `mikopbx_time_sync_offset_seconds` | gauge | — | Отклонение часов от NTP |
| `mikopbx_time_sync_leap_status` | gauge | — | 1 — синхронизация в норме |
| `mikopbx_kernel_oom_kills_total` | gauge | — | Срабатывания OOM killer с загрузки |
| `mikopbx_kernel_panics_total` | gauge | — | Паники ядра с загрузки |
| `mikopbx_modules_total` | gauge | — | Установлено модулей расширений |
| `mikopbx_modules_enabled` | gauge | — | Включено модулей расширений |

> [!note] Необязательные блоки
> Метрики MySQL, nginx, NTP и ядра появляются только если соответствующая
> утилита есть в системе. Отсутствие семейства означает «источник недоступен»,
> а не «ноль». Что именно недоступно — показывает
> `mikopbx_exporter_block_absent_reason`.

## Система

| Метрика | Тип | Labels | Описание |
|---|---|---|---|
| `mikopbx_system_uptime_seconds` | gauge | — | Uptime ОС |
| `mikopbx_system_load1` / `load5` / `load15` | gauge | — | Load average за 1/5/15 минут |
| `mikopbx_system_memory_total_bytes` | gauge | — | Всего RAM |
| `mikopbx_system_memory_available_bytes` | gauge | — | Доступно RAM |
| `mikopbx_system_memory_used_bytes` | gauge | — | Занято RAM (total − available) |
| `mikopbx_system_swap_total_bytes` | gauge | — | Всего swap |
| `mikopbx_system_swap_free_bytes` | gauge | — | Свободно swap |
| `mikopbx_system_user_hz` | gauge | — | Сколько джиффов в секунду (USER_HZ) |
| `mikopbx_system_cpu_seconds_total` | counter | `cpu` (`all`, `0`, `1`, …), `mode` (`user`, `nice`, `system`, `idle`, `iowait`, `irq`, `softirq`, `steal`) | Время CPU по режимам **в секундах** |
| `mikopbx_system_cpu_jiffies_total` | counter | то же | То же в джиффах (устарело, оставлено на переходный период) |
| `mikopbx_system_filesystem_size_bytes` | gauge | `mountpoint`, `device`, `fstype` | Размер ФС |
| `mikopbx_system_filesystem_free_bytes` | gauge | то же | Свободно **всего**, включая резерв ФС |
| `mikopbx_system_filesystem_available_bytes` | gauge | то же | Доступно процессу (без резерва) |
| `mikopbx_system_filesystem_used_bytes` | gauge | то же | Занято = size − free (резерв учтён) |
| `mikopbx_system_filesystem_used_ratio` | gauge | то же | Доля занятого (0..1) |
| `mikopbx_system_filesystem_inodes_total` | gauge | то же | Всего инодов |
| `mikopbx_system_filesystem_inodes_free` | gauge | то же | Свободно инодов |
| `mikopbx_system_filesystem_inodes_used_ratio` | gauge | то же | Доля занятых инодов (0..1) |
| `mikopbx_system_network_receive_bytes_total` | counter | `device` | Принято байт |
| `mikopbx_system_network_transmit_bytes_total` | counter | `device` | Передано байт |
| `mikopbx_system_network_errors_total` | counter | `device`, `kind` (`errors`/`dropped`) | Ошибки и потери на интерфейсе |
| `mikopbx_system_processes` | gauge | — | Количество процессов |
| `mikopbx_system_threads` | gauge | — | Потоков во всех процессах |
| `mikopbx_system_file_descriptors_allocated` | gauge | — | Выделено дескрипторов в системе |
| `mikopbx_system_file_descriptors_free` | gauge | — | Осталось в системной таблице |

> [!warning] Изменение в 1.4.0 — ломающее для дашбордов
> `mikopbx_system_cpu_seconds_total` теперь отдаёт **секунды**, а не джиффы
> (как и обещает имя метрики). Делить на 100 больше **не нужно**:
>
> ```promql
> sum(rate(mikopbx_system_cpu_seconds_total{mode!="idle", cpu!="all"}[5m]))
>   / count(count by (cpu) (mikopbx_system_cpu_seconds_total{cpu!="all"}))
> ```
>
> `cpu="all"` — это сумма ядер, а не среднее, поэтому `cpu!="all"` обязателен.
> Старые значения доступны как `mikopbx_system_cpu_jiffies_total`
> (в 1.4.0 помечены как устаревшие и будут удалены).

| Метрика | Тип | Labels | Описание |
|---|---|---|---|
| `mikopbx_asterisk_up` | gauge | — | 1 — Asterisk отвечает на CLI, 0 — нет |
| `mikopbx_asterisk_info` | gauge | `version` | Версия Asterisk (значение всегда 1) |
| `mikopbx_asterisk_uptime_seconds` | gauge | — | Uptime Asterisk |
| `mikopbx_asterisk_last_reload_seconds` | gauge | — | Секунд с последнего reload |
| `mikopbx_asterisk_channels_active` | gauge | — | Активные каналы |
| `mikopbx_asterisk_channels_by_type` | gauge | `type` | Каналы по технологии (SIP, PJSIP, Local…) |
| `mikopbx_asterisk_calls_active` | gauge | — | Активные вызовы (по данным CLI) |
| `mikopbx_asterisk_calls_processed_total` | counter | — | Обработано вызовов с последнего рестарта Asterisk |
| `mikopbx_queue_callers` | gauge | `queue` | Ожидающих в каждой очереди |
| `mikopbx_queue_active` | gauge | `queue` | Обслуживается в каждой очереди |
| `mikopbx_queue_longest_wait_seconds` | gauge | `queue` | Максимальное ожидание в очереди |
| `mikopbx_queue_longest_wait_max_seconds` | gauge | — | Максимальное ожидание по всем очередям |
| `mikopbx_conferences_active` | gauge | — | Активных конференций |
| `mikopbx_conference_participants` | gauge | `conference` | Участников в конференции |
| `mikopbx_asterisk_channel_quality_max` | gauge | `metric` | Худшее значение RTP-метрики по всем каналам |
| `mikopbx_asterisk_channel_quality_average` | gauge | `metric` | Среднее значение RTP-метрики по всем каналам |
| `mikopbx_asterisk_channel_quality` | gauge | `channel`, `metric` | RTP по каждому каналу (по умолчанию **выключено**) |

> [!warning] Сбрасывается при reload
> `calls_processed_total` обнуляется при каждом рестарте/релоаде Asterisk.
> В Grafana используйте `increase(...[1h])`, а не `rate()` — иначе
> в момент релоада получите отрицательный всплеск.

> [!info] Кардинальность RTP
> Метрика по каждому каналу умножается на число одновременных разговоров
> и быстро съедает TSDB. По умолчанию публикуются только агрегаты
> (`_max` и `_average`); per-channel семейство включается настройкой
> «Публиковать RTP-качество по каждому каналу».

## Вызовы (REST API)

| Метрика | Тип | Labels | Описание |
|---|---|---|---|
| `mikopbx_calls_active` | gauge | — | Активных вызовов всего |
| `mikopbx_calls_active_by_direction` | gauge | `direction` (`incoming`/`outgoing`/`internal`) | Разбивка по направлению |

> [!note] Как определяется направление
> По длинам номеров (как в Zabbix-модуле): оба номера короче 6 цифр —
> внутренний вызов; источник длиннее — входящий; иначе — исходящий.

> [!tip] LLD больше не нужен
> В Prometheus «дискавери» транков не требуется: метки `trunk` и `name`
> появляются на каждом скрейпе, исчезнувший транк просто перестаёт
> выдавать серии (stale).

## Статистика звонков по транкам (скользящее окно)

Считается фоновым коллектором раз в 5 минут по данным CDR. Период — `hour` или `day` (последний час / последние сутки на момент сбора).

| Метрика | Тип | Labels | Описание |
|---|---|---|---|
| `mikopbx_trunk_calls` | gauge | `trunk`, `name`, `period`, `direction` | Всего вызовов |
| `mikopbx_trunk_calls_answered` | gauge | то же | Отвеченных |
| `mikopbx_trunk_calls_duration_seconds` | gauge | то же | Суммарная длительность, сек |
| `mikopbx_trunk_calls_billsec_seconds` | gauge | то же | Суммарный billsec, сек |
| `mikopbx_trunk_answer_rate_ratio` | gauge | то же | ASR: отвеченные / всего (0..1) |
| `mikopbx_trunk_average_billsec_seconds` | gauge | то же | ACD: отвеченный billsec / отвеченные |
| `mikopbx_trunk_average_ring_seconds` | gauge | то же | Среднее время звонка |
| `mikopbx_trunk_average_hold_seconds` | gauge | то же | Среднее время удержания |
| `mikopbx_trunk_calls_by_disposition` | gauge | `trunk`, `name`, `period`, `disposition` | Разбивка по причине завершения |
| `mikopbx_trunk_short_calls` | gauge | `trunk`, `name`, `period`, `direction` | Короткие отвеченные вызовы (< 5 сек) |
| `mikopbx_trunk_long_calls` | gauge | то же | Длинные отвеченные вызовы (> 600 сек) |
| `mikopbx_extension_missed_calls` | gauge | `period`, `extension` | Пропущенные входящие по внутреннему номеру |
| `mikopbx_stats_cache_last_update_timestamp_seconds` | gauge | — | Unix-время последнего обновления кэша |
| `mikopbx_stats_cache_age_seconds` | gauge | — | Возраст кэша, сек |
| `mikopbx_stats_cache_missed_error_age_seconds` | gauge | — | Сколько секунд назад сломался источник пропущенных (0 — работает) |

> [!warning] Это gauge, а не counter
> Значения относятся к скользящему окну и могут уменьшаться
> (вызовы «выпадают» из окна). Не применяйте к ним `rate()`/`increase()`.
> Свежесть данных контролируйте через
> `mikopbx_stats_cache_age_seconds` — если он растёт, cron-коллектор упал.

> [!info] Пропущенные не исчезают при сбое источника
> Если `cdr:getMissedCallsByExtension` временно недоступен, прежние
> значения остаются в кэше, а
> `mikopbx_stats_cache_missed_error_age_seconds` показывает, сколько
> секунд назад сломался источник. Раньше метрика просто исчезала,
> и это выглядело как «никто ничего не пропустил».

## Пример вывода

```text
# HELP mikopbx_sip_peers_online SIP peers in a responsive state
# TYPE mikopbx_sip_peers_online gauge
mikopbx_sip_peers_online 12

# HELP mikopbx_trunk_up Trunk state as a number (1 = registered or OK, 0 = anything else)
# TYPE mikopbx_trunk_up gauge
mikopbx_trunk_up{trunk="SIP-PROVIDER-1",name="Ростелеком"} 1
mikopbx_trunk_up{trunk="SIP-PROVIDER-2",name="Резерв"} 0
```

## Полезные PromQL

```promql
# Сеть на интерфейсе (байт/с)
rate(mikopbx_system_network_receive_bytes_total{device="eth0"}[5m])

# Свободное место на /storage
mikopbx_system_filesystem_free_bytes{mountpoint="/storage"}
  / mikopbx_system_filesystem_size_bytes{mountpoint="/storage"}

# Все вызовы по направлениям
sum by (direction) (mikopbx_calls_active_by_direction)

# Упавшие транки
mikopbx_trunk_up == 0

# Экспортёр жив и отдаёт метрики
mikopbx_exporter_up == 1 and mikopbx_exporter_scrape_families > 0

# Что именно не отдаёт данные
mikopbx_exporter_block_absent_reason
```
